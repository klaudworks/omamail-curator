# Support and unclear behavior

Answer usage/configuration questions from documentation and current source. Read the existing answers and inspect relevant attachments. Use `support` for a usage question, or `disputed` when the intended behavior is genuinely unclear; both map to `question`. Do not label a report `bug` when the evidence instead suggests a valid feature-minimum message or expected configuration behavior.

Explain the useful answer directly. Ask the creator a focused follow-up only when a missing fact prevents resolution; use `needs-information` with an author next step. When an existing answer is sufficient, avoid turning your inability to observe the user's installation into a new blocker. Use [EVIDENCE.md](EVIDENCE.md) for checks you can perform yourself.

Route an established defect to [ISSUE-BUGS.md](ISSUE-BUGS.md), a small requested improvement to [ISSUE-CHANGES.md](ISSUE-CHANGES.md), or a substantial addition to [ISSUE-FEATURES.md](ISSUE-FEATURES.md). For mixed questions, answer the verifiable parts and isolate the actual product decision. Match the report's language when practical.

Finish with [REPORT.md](REPORT.md).
