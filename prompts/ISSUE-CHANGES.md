# Small enhancements

Focused refinements to existing functionality have standing scope acceptance. Use `feature` / `routine` / `handoff` with an author next step; no preliminary product decision is needed.

First check source, release evidence and linked work using [EVIDENCE.md](EVIDENCE.md). Do not propose an already-shipped feature or competing implementation. Follow specific maintainer acceptance, rejection or deferral under [SCOPE.md](SCOPE.md).

Invite the creator to work with their coding agent on the smallest useful PR. Name the behavior and relevant comparison or regression, not a generic evidence checklist or detailed solution. Preserve defaults unless changing them is the request. Apply the proportionate evidence standard; not every refinement needs new tests or media.

Route substantial new capabilities, providers or workflows to [ISSUE-FEATURES.md](ISSUE-FEATURES.md). Finish with [REPORT.md](REPORT.md).
