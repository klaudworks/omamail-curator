# Incremental review decisions

The controller checks eligibility first. Completeness can run before CI succeeds; final review and reuse/publication of final assessments require successful current-head CI. Unchanged inputs need no model. Initial assessments always run; a verified unchanged public checkpoint can establish a private baseline without another review.

With `decision_token_file` configured, changed inputs are compared with the **last full assessment**, never just the last skipped update. Jev receives the previous assessment, complete baseline discussion, accumulated additions/edits/removals, current title/description, author/maintainer identities, and PR source deltas. Inline-review context includes filenames, lines and diff hunks. Lossless references represent unchanged fields and edited-comment preimages once; changed text and baseline discussion are never truncated. Identical immutable head/base revisions require no Git collection or duplicate contribution diff.

The same context is delivered to detailed reviewers as `changes.json`, with the chosen route added. Native evidence-read validation requires reviewers to open it. Workflow context identifies triage, completeness or final review, the retained completeness assessment, outstanding blockers and the previous next step.

## Routing

- Use `jev-1.14.0` at the official TypeSafe `/v1/systemone` endpoint. Ask positively whether another assessment can reasonably be skipped. Skip when `P(can_skip) > 0.75`; exactly 0.75 or lower proceeds to review. This same threshold applies to ordinary updates and verified branch-sync merges.
- Corroborating reviews/results on already-ready unchanged code can be nonmaterial. New facts need not change the decision. Credible defects, contradictions and evidence resolving an outstanding request still warrant assessment; agreement alone cannot erase a blocker.
- New or removed linked evidence requires review, including screenshots/videos. Jev never assumes it has inspected a URL's contents. Experimental image support is not used.
- Behavioral contributor edits, binary changes and incomplete source collection require review. These deterministic decisions cannot be overridden by Jev. Nonfunctional documentation is eligible for a skip decision, not automatically skipped.
- For a PR with retained passing completeness, the same decision request also asks `can_reuse_completeness`. Ordinary follow-ups and final-review findings can retain the milestone; withdrawn evidence or materially changed prerequisites can return to completeness. Reuse requires strictly above 0.75. Insufficient/oversized context cannot justify reuse in this routing decision. The reviewer verifies the affected prerequisites; the decider never grants a pass. Initial assessments or missing private baselines use the existing milestone and current evidence directly; a disabled decision service preserves the prior deterministic stage selection.
- For branch-sync merges, independently reproduce the two-parent merge using its merge base, confirm the other parent belongs to the target branch, and compare the computed tree with the actual commit. Extra edits and conflict-resolution changes fail this check. Supply incoming upstream changes and the full current contribution diff so Jev can judge interactions.
- Only a verified branch-sync with unchanged title, description and discussion uses the merge-specific question. A clean Git merge alone is insufficient. Existing unresolved findings remain in force.
- The score is a routing threshold, not a demonstrated correctness rate. This deliberately favors avoiding repeat work when skipping is reasonably supported, rather than requiring near-certainty. API/network/output failures wait for another cheap decision attempt instead of triggering expensive reviews.

The transport body is capped at 96,000 UTF-8 bytes; the API's default 32k-per-question/64k-per-request token limits remain authoritative. Bytes are not treated as exact token counts. A local size rejection or API context-limit rejection goes to full review, with no truncation and no automatic 262k long-context opt-in.

## State and publication

Private baselines and decisions live under `state_dir/relevance/`, anchored to the current signed public status comment. Cache each successful skip by the baseline/current fingerprints, model, questions and threshold, so repeated polling makes zero model calls. Changing the question or threshold invalidates only cached skip decisions, preserving full assessments. Removing or changing the signed anchor invalidates the baseline. Skipping never advances the reviewed source SHA, marks a new commit reviewed, or grants readiness; new head/base changes remove stale `review-ready`.

A private evidence-policy marker reopens older PR `needs-information` results once. Pending old information requests also require reassessment. Ready, blocked and scope-decision assessments keep their existing contracts and reuse behavior. Signed progress comments are excluded from assessment selection and discussion deltas.

Save completed assessments before publication so a failed comment/label request can reuse model work. Discover signed comments before retrying writes. Initial issue triage always posts one comment. For issue follow-ups, explicitly ask whether posting another comment can reasonably be skipped, comparing the new assessment with the latest public one and the complete current human discussion, issue description and author/maintainer identities. The previous public comment's ID and timestamps locate intervening replies. Reworded demands, repeated human questions and premature implementation choices do not justify another comment without useful new information or action. The same `P(can_skip) > 0.75` rule suppresses the comment; exactly 0.75 or lower publishes it. A changed category/state/owner/disposition publishes directly. PR assessments retain one-comment-per-assessment history.

Completed work also retains its original discussion and CI basis. Before publication, appended discussion may receive one cheap recheck against that completed assessment. Source, author, title and description must match; final assessments additionally require matching successful CI. Completeness is independent of CI progress. Edits, deletions and changed links require fresh assessment. Only `can_skip > 0.75` permits publication against the newer snapshot. Cache the recheck for that exact input, include its model/score/comment IDs in the signed checkpoint, and retain the original fully-assessed baseline. Later additions are compared cumulatively against that basis. Publisher freshness checks still apply throughout writes; a race can retry the same retained result without creating a duplicate assessment comment. Missing private context for a reconciled public checkpoint causes fresh processing rather than inventing an assessed baseline.

## Initial evaluation

A small historical discussion replay used ten examples during initial prompt refinement and six held-out examples. The original stricter question skipped all eight nonmaterial updates and retained all eight substantive ones. A read-only replay of the image-downscaling branch sync verified its exact merge tree, skipped the independent upstream change, preserved the previously reviewed SHA, and made zero calls on the repeated decision. Synthetic merge contrasts covered unrelated documentation and an interacting image-limit change. These checks establish basic fit, not a statistically measured miss rate; inspect saved decisions when assessing later performance or changing thresholds.

Replaying those same sixteen discussion updates with the positive `can_skip > 0.60` rule skipped nine and retained seven. The additional skip was a short successful-retest confirmation on an already-verified fix, previously categorized as new evidence. Diagnostic findings, changed requirements, maintainer direction and the new-provider report still reached review. This reused sample is a regression comparison, not a new held-out accuracy measurement.

With the positive question, the real independent branch-sync scored 0.84 for skipping; a synthetic interacting image-limit change scored 0.29 and reached review. The comment decision scored 0.99 for skipping an identical assessment and 0.06 for a synthetic useful correction. Boundary checks confirmed that 0.60 publishes/reviews and 0.61 skips.

The operator subsequently raised the shared threshold to strictly above 0.75. Applying it to the saved scores leaves these replay/contrast outcomes unchanged. Updated boundary checks confirm that 0.75 reviews/publishes and 0.76 skips.

The November 2026 friction audit replayed the corroborating discussions on PRs #442 and #444 with compact context: both scored 0.97 for skipping. Concrete-regression contrasts scored 0.04–0.05 for skipping while retaining completeness (0.87–0.93), routing them to final review. A material scope change with missing entry inputs scored 0.16 for completeness reuse. These are targeted regressions, not measured accuracy. Real sandbox sessions also passed original #447 completeness with its existing Gist evidence, answered a support question and requested a genuinely missing bug reproduction, reading each applicable guide once.
